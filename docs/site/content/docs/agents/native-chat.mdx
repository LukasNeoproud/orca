Chat UI is an experimental conversation view for supported agents. Terminal-backed chat reads the agent's transcript and sends input to its terminal. With **Codex and Claude chats** enabled, explicit **New Codex Chat** and **New Claude Chat** actions start the provider's structured runtime. Transcript decoding for terminal-backed chat also covers **Grok** and **OMP**.

## Enable

1. Open **Settings → Experimental → Chat UI**.
1. Turn **Chat UI** on.
1. Optionally set **Default view** to **Chat UI** so new supported agent tabs open in chat; keep **Terminal** to open the TUI first.
1. Enable **Codex and Claude chats** for dedicated structured sessions. This works with either default view.
1. Set **Session history default** to choose whether a saved Codex or Claude conversation opens in its terminal or in Chat UI.

The session-history preference applies when you reopen saved conversations. New agent tabs use their own launch actions. Ordinary orchestration workers start terminal-backed unless a structured worker workflow explicitly selects Chat UI.

Toggle Chat UI ↔ terminal from the agent pane once enabled.

## Structured chat

Structured Codex chat offers provider-reported **Model**, **Effort**, **Fast mode**, and **Permissions** controls without clearing the message you are writing. **Permissions** has its own dropdown, separate from effort and fast mode. Available choices follow the running provider and its account or managed configuration. **Auto review** is a selectable mode that keeps the workspace sandbox and routes approval requests to Codex's reviewer. A provider-reported combination outside the supported presets still appears as **Custom**, with its active policy shown in the menu.

Switching an existing Codex or Claude terminal to Chat UI changes its view while keeping the same terminal process, conversation, draft, and attachments. Use **Show terminal** to switch back. Dedicated structured chats have their own launch actions and do not offer this terminal-view toggle.

Structured launch availability follows the workspace's execution host. Unsupported hosts show an explanation rather than launching a different runtime or a local replacement. Previously started transfer operations retain their recovery controls.

Each workspace card has a collapsed **Conversation History** section. The first expansion loads that execution host's complete session catalog, shared across its workspace cards. Expand it to see the workspace's five newest unopened primary sessions as compact rows with an agent icon, title, and relative time. Select a row to use the session-history preference. The row menu always shows explicit **Open in Terminal** and **New Codex Chat** or **New Claude Chat** actions. Orca disables an unavailable action and explains why. The **Show full history** icon in the section header opens Agent Session History with that workspace and execution host selected, even while the section is collapsed.

## Context usage

The Codex context ring shows how much of the context window is in use. The colored arc, with the same width as the rest of the ring, marks the range from the automatic compaction threshold to 100%. Hover or focus the ring for the token counts, remaining tokens until compaction, and the source of the threshold; click to keep the details open. Stale usage is labeled, and thresholds measured only after the prompt prefix are shown as text rather than as a percentage of the whole window.

## Composer

- Type a message and send (or stop a working turn). Attach files/images when the host supports it. Unsent draft text and attachments stay with the pane across disconnect/reconnect when the host can restore them. A settled transcript also stays on screen while the same session reconnects, instead of blanking until the fresh load finishes (desktop and mobile share that retention).
- Type `/` for slash commands and discovered **skills** (filtered per agent when possible). The slash catalog is agent-aware (Claude vs Codex command sets) and shared with mobile Chat UI.
- Use the **model** and options pills (thought level, mode, agent-specific session options) when the agent exposes them. **Claude** model choices come from the **installed Claude CLI on that host** (not a hardcoded list), so new models show up after you update the CLI. Terminal-backed **Codex** chat may still require the agent's picker; enable structured chat for independent session controls. **Grok** exposes **model** (`-m` at launch, `/model` mid-session) and **reasoning effort** (`--reasoning-effort` at launch, `/effort` mid-session); the model list is probed from the signed-in Grok CLI (`grok models`) so retired ids drop out of the picker. Effort choices follow the selected model: Grok 4.6 includes **Extra high**, while Grok 4.5 stops at **High**. **Before the agent process starts**, the composer can show draft launch options that apply on first start; after the session is live, pills that only affect a running turn stay disabled or labeled until the session is ready.

## Questions from the agent

When Claude shows an **AskUserQuestion** (or similar structured permission/question card), Chat UI should render the question card in the transcript so you can answer from the composer path instead of treating it as a collapsed tool call. Confirm with **Submit** on the card. That includes agents running on a paired [Remote Orca Server](/docs/remote-servers) / headless host — not only local panes.

## Availability

Chat UI ships on desktop for supported local and remote (paired server) agent sessions. The [mobile companion](/docs/mobile) reuses chat-style transcript patterns for the same paired sessions.
